# Functions the JAR speeds up

The GeoBrix JAR adds a JVM level (L1) to some functions. On a dedicated cluster with the JAR, these functions run in the JVM instead of in a Python worker.

The env wheel alone runs every function. The JAR is optional: install it only where you want the JVM level.

The JAR is a performance tier, not an API. You call every function from SQL or Python, and GeoBrix picks the JVM level where it is faster. The **Scala** tag on a function's API page links here. For the measured speed-ups, see [Performance with the JAR](./performance#heavy-level-with-the-jar) and the [benchmark results by function](./benchmarking#levels-by-function).

## Where the JAR loads

- **Dedicated access mode** loads the JAR. The functions on this page run on the JVM there.
- **Standard access mode** runs Spark Connect, so no function has a JVM level there. GeoBrix runs the Python level and says why.
- **Serverless** cannot load the JAR. Every function runs at its Python level.
- **A SQL warehouse** runs Unity Catalog functions only. See [Unity Catalog functions](./uc-functions).

[What needs dedicated compute](./execution-tiers#dedicated-compute) compares the computes feature by feature.

## Which functions run on the JVM

:::tip The keep rule
**GeoBrix makes the JVM level the default where it measured at least 1.2x faster than the best Python form, with the same output.**
:::

A few functions are not measured yet. They run the JVM level until a measurement says otherwise.

[Performance](./performance#heavy-level-with-the-jar) has the measured speed-ups. Every function not listed here runs at its Python level, with or without the JAR.

A note "A virtual tile runs in Python" marks a tile function that reads bytes on the JVM. GeoBrix sends a virtual tile to the Python level, and a materialized tile to the JVM. See [Virtual tiles and the JVM level](./execution-tiers#light-heavy-bridge).

## Check the level GeoBrix picked

`register` returns the level it chose for each name:

```python
from databricks.labs.gbx import register

chosen = register(spark)
chosen["gbx_rst_width"].level   # 'L1' on dedicated compute with the JAR, else 'L3'
```

When the JVM level cannot run, `register` prints one line that names the level and the reason. See [GeoBrix says why](./execution-tiers#geobrix-says-why).

## Install the JAR

- [Choose an install path](../installation.mdx#choose-an-install-path) compares the env wheel alone, the env wheel and the JAR, and a container image.
- `databricks.labs.gbx.stage_jar(vol_dir)` copies the JAR of the env wheel to a Volume folder. See [Stage the JAR](../installation.mdx#stage-jar).
- A [DCS image](../installation/dcs.mdx) starts a dedicated DBR 19 cluster with the JAR in place.
