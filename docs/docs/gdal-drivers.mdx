# GDAL drivers as provided

The GeoBrix env wheel ships one GDAL build. This page lists the drivers of that build, with what each can do.
Use it to check whether a format is in the wheel before you install anything.

The list shows the drivers **as provided**. It does not change when you add or remove packages.
To see the drivers your current environment can run, call [`gbx_drivers()`](./api/general-functions#drivers).
That function reads GDAL as it runs now, so its rows can differ from this table.
Its `shipped` column is false for a driver that is not in this list.

GeoBrix tests some drivers through its distributed readers and writers, and the tables mark them as <span className="gbx-tested">Tested</span>.
A driver that is not tested may work, but it is use-at-your-own-risk.
The tested set describes this release, not the environment you run in, so `gbx_drivers()` reports it in its `tested` column.
The env wheel's GDAL has no Parquet or GeoParquet, Arrow, HDF4 (MODIS), LIBKML or PostgreSQL driver.

GeoBrix [turns off](./security#7-raster-data-other-principals-can-write) some drivers by default and does not register them.
They are not in the tables below, and `gbx_drivers()` does not return them either.
See [GeoBrix Opt-In Drivers](#geobrix-opt-in-drivers) for the list and how to opt in.

```sql
SELECT driver, description, requires FROM gbx_drivers() WHERE NOT available
```

## How to read the tables

- **Read** and **Write** are GDAL's flags: it can open a dataset, and it can create or copy one.
- **Tile bytes** is set when a raster of this driver can be held as the bytes of a tile.
- **Requires** names what the driver needs besides the data file. A format with sidecar files names them here.
- **Why** names what an unavailable driver needs: a service, a program or a plugin that this runtime lacks.
- **GeoBrix built-in** links to the first table, when a GeoBrix reader or writer handles the format without this driver.
- **Tested with GeoBrix** lists the GeoBrix reader, writer or function that the tests used. A tested row has a green tint and the label <span className="gbx-tested">Tested</span>, so colour is not the only cue.
- **GeoBrix guidance** names the built-in reader, writer or function to use for the format, and what it covers. It links the pages that explain it. `gbx_drivers()` returns the same note in `guidance`, and the links in `docs`.
- Each table has three groups: available and tested, available and not tested, and unavailable.
- A driver for both rasters and vectors is in both tables, and each row links to the other one. It can be tested as one kind only.

## Formats GeoBrix handles without a GDAL driver

These GeoBrix readers, writers and functions do not use the GDAL driver of the same format.
Their path does not depend on the driver rows below.
A format that GeoBrix reads through rasterio or pyogrio, such as GeoTIFF or GeoPackage, uses its driver.

| Format | GDAL driver | What GeoBrix uses instead | Where |
|---|---|---|---|
| <Link id="builtin-zarr"></Link>Zarr | [`Zarr`](#raster-zarr) | The zarr package, with tensorstore or zarrs as optional engines. | `zarr_gbx` (reader and writer), `gbx_zarr_read`, `gbx_zarr_write` |
| <Link id="builtin-netcdf"></Link>netCDF | [`netCDF`](#raster-netcdf) | xarray with the netCDF4 engine to read, and netCDF4 to write. The COG writer and raster functions that open a netCDF file still use the GDAL driver. | `netcdf_gbx` (reader and writer) |
| <Link id="builtin-pmtiles"></Link>PMTiles | [`PMTiles`](#vector-pmtiles) | The pmtiles package. | `pmtiles_gbx` (reader and writer), `gbx_pmtiles_agg`, `pmtiles_info` |
| <Link id="builtin-mvt"></Link>Mapbox Vector Tiles | [`MVT`](#vector-mvt) | The mapbox-vector-tile package. | `gbx_st_asmvt`, `gbx_st_asmvt_pyramid`. The PMTiles writer stores the encoded tiles as they are. |
| <Link id="builtin-exif"></Link>EXIF and GPS image metadata | [`JPEG`](#raster-jpeg) | Pillow and exifread. The JPEG driver reads pixels only. | `exif_gbx` (reader) |
| <Link id="builtin-lidar"></Link>LiDAR point clouds (LAS and LAZ) | none | The laspy package. | `lidar_gbx` (reader and writer) |

## GeoBrix Opt-In Drivers

These drivers are off by default. You can opt in to them, and then you own the risk.
GeoBrix keeps each one off because it reaches a network service, runs a stored pipeline, or acts on what a file names.
A file that another principal wrote can then make your cluster send requests or run a pipeline.

### What the policy does

- **It covers the whole Python process.** It is not limited to GeoBrix functions.
  It adds these drivers to `GDAL_SKIP` and removes them from each GDAL that the process has loaded.
  A direct `from osgeo import gdal` in the same process therefore lacks them too.
- **It starts when GeoBrix is imported.** The import adds the drivers to `GDAL_SKIP`, and sets the two VRT settings.
  The first GeoBrix use of GDAL completes it. The env wheel's startup file only prepares the native libraries.
  The call `register(spark)` does not start the policy itself, because the import has done it.
- **To opt in, set `GBX_GDAL_DRIVER_POLICY=off` before `import databricks.labs.gbx`.**
  A value set after the import has no effect. GeoBrix has already added the drivers to `GDAL_SKIP`.
- **Set it where each process can read it.** The driver and every executor read the variable in their own Python process.
  Set it in the cluster's environment variables, or the job cluster's, to reach all of them.
  A notebook assignment of `os.environ` before the import reaches the driver only. A worker still applies the policy.
  On the JVM, set `spark.databricks.labs.gbx.gdal.driver_policy=off` in the Spark config, or the same variable in the cluster's environment.
- **Off removes the whole defence for that process.** The VRT raw-band and Python settings stay as GDAL has them.
  Prefer a separate process or job for work on data you trust and that needs one of these drivers.
- **The live view changes too.** `gbx_drivers()` lists these drivers only when the policy is off.

See [The policy covers the whole process](./security#the-policy-covers-the-whole-process) on the Security page.
