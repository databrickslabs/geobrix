# GeoSAM Segmentation

GeoSAM wraps [segment-geospatial](https://samgeo.gishub.org/) (SamGeo) as a `gbx.models`
backend: load a handle once, then segment a whole raster — of any size — into
georeferenced object polygons with `segment_raster`. Today GeoSAM runs in **automatic-mask
mode**, which segments everything with no prompt. Text-prompt-guided segmentation (segment only
objects matching a text description) is a natural follow-on, not yet implemented.

## Loading a handle

```python
from databricks.labs.gbx.models import load_geosam

handle = load_geosam(model_type="vit_h", weights=None, device="cuda")
```

`load_geosam(*, model_type="vit_h", weights=None, device="cuda")` builds a SamGeo backend
in automatic-mask mode and returns a `GeoSamHandle`. `torch` and `segment-geospatial` are
imported lazily inside this call, not at module import time — a caller without the GPU
deps installed gets a clear `ModelDepsMissing` error:

```
GeoSAM requires the model deps: install them after the env wheel on Serverless GPU (env6 wheel, environment 6; pip install torch==2.9.0 torchvision==0.24.0 segment-geospatial opencv-python-headless==4.11.0.86)
```

- `model_type` — the SAM model variant (default `"vit_h"`).
- `weights` — optional path to a local checkpoint; `None` defers to SamGeo's default
  weight resolution, which downloads `sam_vit_h_4b8939.pth` from Meta's CDN.
- `device` — `"cuda"` (default) or `"cpu"`.

## Segmenting a single image

`segment(handle, image)` is the low-level per-image call: given an `HxWx3` uint8 array, it
returns an `HxW` int32 label mask (`0` = background, `1..N` = distinct objects). Most
callers use `segment_raster` instead, which handles chipping, georeferencing, and
polygonization on top of this call.

## Segmenting a raster — `segment_raster`

```python
from databricks.labs.gbx.models import segment_raster

df = segment_raster(
    "/Volumes/catalog/schema/volume/orthomosaic.tif",
    gpus="all",
    tile_px=1024,
    overlap=6,
    min_area=10.0,
)
# df: pandas.DataFrame with columns label (int), geom (WKB bytes), score (float)
```

`segment_raster` is the single call a notebook makes to go from a raster to a set of
georeferenced object polygons — chip → infer → stitch → polygonize:

1. **Chip** — the input is split into an overlapping grid of `tile_px` × `tile_px`
   windows via the same overlap-percentage window planner GeoBrix uses for
   `gbx_rst_tooverlappingtiles`.
2. **Infer** — each chip is segmented by GeoSAM (or an injected `segmenter`), fanned across
   1..N GPU device slots. With the default GeoSAM backend, each device gets its own
   handle. The handle is bound to that device and cached across every chip it processes. It is never shared
   with another device and never rebuilt per chip.
3. **Stitch** — each chip's label mask is vectorized into georeferenced WKB polygons using
   its own true per-window transform. NoData pixels are background in the mask, so a black
   or transparent border is never an object. The fragments of one object that a seam cut
   apart are merged into one polygon per real-world object (see
   [How seams are merged](#how-seams-are-merged)).
4. **Polygonize / filter** — merged polygons smaller than `min_area` (in square meters)
   are dropped.

### Signature

```python
segment_raster(
    tile_or_path,
    *,
    segmenter=None,
    weights=None,
    model: str = "geosam",
    gpus="all",
    tile_px: int = 1024,
    overlap: int = 6,
    min_area: float = 10.0,
) -> pandas.DataFrame
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `tile_or_path` | dataset / bytes / path | — | An open `rasterio` dataset, raw GeoTIFF bytes, or a file path. |
| `segmenter` | callable | `None` | Injectable `(image: HxWx3 uint8) -> mask: HxW int`. Defaults to a GeoSAM handle when `None`. |
| `weights` | `str` | `None` | Path to a GeoSAM checkpoint file: a local, `/Volumes/...` or `dbfs:/Volumes/...` path. `None` lets SamGeo download the default checkpoint. Cannot be combined with `segmenter`. |
| `model` | `str` | `"geosam"` | Which built-in backend to use when `segmenter` is `None`. Only `"geosam"` is implemented today; pass `segmenter=` explicitly for anything else. |
| `gpus` | `"all"` or `int` | `"all"` | `"all"` probes `torch.cuda.device_count()` (lazy `torch` import); a positive `int` passes through untouched and **never** imports `torch`. |
| `tile_px` | `int` | `1024` | Square tile size in pixels. |
| `overlap` | `int` | `6` | Seam overlap as a **percentage of tile size** (`0`-`100`; matches `rst_tooverlappingtiles`) — not a pixel count. E.g. `overlap=6` on `tile_px=1024` is a ~61px seam. |
| `min_area` | `float` | `10.0` | Minimum object area in **square meters** — polygons smaller than this (after seam-merge) are dropped. Measured metrically whatever the source CRS: geodesic area for a geographic CRS (e.g. EPSG:4326), planar for a projected one. |

Returns a `pandas.DataFrame` with columns `label` (`int`), `geom` (`bytes`, WKB), and
`score` (`float`). `score` is currently a constant `1.0` — a bare label mask carries no
per-object confidence; it will carry a real score once a confidence-scored backend is
wired up.

### Workspaces without internet egress

By default SamGeo downloads the checkpoint `sam_vit_h_4b8939.pth` from Meta's CDN. Many
workspaces block that egress. Stage the file on a Volume once, then pass its path as `weights`:

```python
df = segment_raster(
    "/Volumes/catalog/schema/volume/orthomosaic.tif",
    weights="/Volumes/catalog/schema/volume/models/sam_vit_h_4b8939.pth",
)
```

A `dbfs:/Volumes/...` URI works too. A missing file raises `FileNotFoundError` with the path.
`weights` cannot be combined with `segmenter`, because an injected segmenter loads no checkpoint.

### Choosing `gpus`

- `gpus="all"` (default) — probe every visible GPU and fan chips across all of them.
- `gpus=1` — force single-GPU (or CPU-adjacent single-device) execution. Passing an
  explicit `int` never imports `torch`, so this path stays usable even without a CUDA
  build installed.
- `gpus=<N>` — cap the fan-out to `N` device slots.

The single-GPU and multi-GPU paths recombine every chip's polygons into the same result
set — scheduling more chips across more devices changes throughput, not output.

### How seams are merged

SAM's automatic masks cover nearly the whole scene, so neighbouring objects touch. Merging
every pair of polygons that touch would chain a whole scene into one or two blobs.
`segment_raster` merges two fragments only when they are the two sides of one object cut by
a chip seam:

- They come from **different chips**. The polygons of one chip are never merged with each
  other: within a chip, the segmenter's own labels are the objects.
- With `overlap > 0`, both chips see the object in their overlap zone. Each chip's fragment
  is vectorized with its own true per-window transform, so both land on the same real-world
  footprint there. They are merged when, clipped to the overlap zone, their
  intersection-over-union is at least 0.5.
- With `overlap=0`, the chips only abut. The fragments must share an edge along the seam
  line, at least one pixel long and covering at least half of their edges on the seam. A
  shared edge elsewhere, or a single shared corner point, is not a seam.

`min_area` is judged on the merged object.

### NoData

A pixel the raster marks invalid is background in every chip's mask before polygonizing:
a NoData value, a mask band, or alpha 0. A raster that declares none of them, such as a
3-band orthomosaic with a black border, treats a pixel that is 0 in every band as NoData.
The segmenter is given the color bands only; an alpha band is left out.

## Automatic-mask mode (today) vs. text-prompt mode (follow-on)

GeoSAM runs SamGeo's **automatic-mask** mode: it segments every distinct object it finds
in a chip, with no guidance about what to look for. This is the mode `load_geosam` /
`segment_raster` use today.

SamGeo also supports **text-prompt-guided** segmentation, which returns only objects matching a
description, e.g. `"building"` or `"tree"`. It is a natural extension of this backend
but is **not implemented** in the current `gbx.models` package. It is a follow-on
capability, not something to invoke today.

## Installation

```
%pip install "geobrix[vizx] @ file:///Volumes/.../geobrix-0.6.0+env5-py3-none-any.whl"
%pip install "torch==2.9.0" "torchvision==0.24.0" "segment-geospatial" "opencv-python-headless==4.11.0.86"
```

On Databricks the GeoSAM packages are a separate step after the env5 wheel, because the env wheels have no
models extra. They are `torch==2.9.0` / `torchvision==0.24.0` (CUDA 12, the Serverless **GPU AI Runtime
environment 5** base's pair), OpenCV 4.x, and `segment-geospatial`. The last one also installs PyPI's
`rasterio` and `shapely` beside the wheel's own (a GeoBrix process uses the wheel's). See [Geospatial Models
overview](./overview#installation).
