# Quick Start

This guide will help you get started with GeoBrix quickly after installation. All code below is copy-paste executable when you use the sample data paths shown.

## Install and register

Install the env wheel for your runtime, then register once per session. One wheel covers **RasterX** (every `rst_*` function), **VectorX** (`gbx_st_*`) and **GridX** (`gbx_bng_*`, `gbx_quadbin_*`, `gbx_custom_*`, `gbx_h3_*`), plus the readers and writers. It runs on Serverless, standard and dedicated clusters, ARM and Lakeflow pipelines.

```python
# Stage the env wheel for your runtime in a Unity Catalog Volume (+env6: Serverless environment 6
# and DBR 19; +env5: environment 5 and DBR 17.3 / 18), then install it with the quoted
# PEP 508 "name @ file://" form (Serverless-safe); add feature extras as "geobrix[vizx] @ ...":
%pip install "geobrix @ file:///Volumes/<catalog>/<schema>/<volume>/geobrix-<version>+env6-py3-none-any.whl"

from databricks.labs import gbx
gbx.register(spark)   # the gbx_* SQL functions and the *_gbx readers and writers
```

:::warning Quote the `geobrix[<extras>] @ file://…` requirement
Install with the **named, quoted** form above. Do **not** put an extra on the
path (`'/Volumes/…/…whl[vizx]'`). On **Serverless**, `%pip` writes the
requirement to a file *including the quotes*. Pip then reads `[vizx]` as part of
the filename and fails. The error is *"Expected package name at the start of dependency
specifier."* The named form installs cleanly on Serverless, standard/shared,
and ARM.
:::

GeoBrix picks the faster implementation the compute offers and says why when it falls back. A dedicated cluster can also add the GeoBrix JAR. See [Installation](./installation) for the install paths and [Surfaces and levels](./api/execution-tiers) for how GeoBrix picks.

:::tip Set up sample data first
The examples on this page use **sample data paths** (e.g. `/Volumes/.../geobrix-examples/nyc/...`). To run them as-is, set up sample data first: **[Sample Data Guide](./sample-data/overview)** — then use the same paths or volume in your notebook.
:::

## Reading Data

Paths below assume the [Sample Data](./sample-data/overview) layout (e.g. Essential Bundle). The `*_gbx` readers are pure Python (no GDAL/OGR install) and run on every compute. To keep a table in sync with a landing folder rather than read it once, see [Ingestion Pipelines](./ingestion/overview).

`gbx.register(spark)` registers the readers. Load by format string (`gtiff_gbx` / `raster_gbx` for rasters; `shapefile_gbx` / `geojson_gbx` / `gpkg_gbx` / `file_gdb_gbx` for vectors).

:::note Virtual tiles by default
The raster reader returns **[virtual tiles](./api/virtual-tiles)** by default. Each row
carries a bytes-free `(path, window)` reference instead of the raster pixels, so a large file fans
into tiles without accumulating memory. Pass `.option("virtualTiles", "false")` (or use
`materialize=True` on a downstream `rst_*` call) when you need the bytes in-row.
:::
