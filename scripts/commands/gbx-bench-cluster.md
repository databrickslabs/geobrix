# gbx:bench:cluster

Submit the heavy-vs-light benchmark as a one-off notebook job to a **provisioned** Databricks cluster. Both APIs run on the same cluster (the true same-hardware comparison); results append to the `bench_results` Delta table and `comparison.csv`/`summary.md` land on the configured Volume.

**Prerequisites (operator):** a provisioned cluster + filled `examples/tests/databricks_cluster_config.env`. Heavyweight needs an x86 DBR 17.3 or 18 LTS cluster with the init script + bundle + geobrix wheel + the bench `geobrix-*-tests.jar` staged; lightweight (incl. ARM) needs the env wheel for the runtime (`geobrix-<version>+env5` on DBR 17.3 / 18, `+env6` on DBR 19 and Serverless environment 6; no light extra). On ARM clusters use `--lightweight-only` (heavyweight is x86-only by design).

**Usage:** `bash scripts/commands/gbx-bench-cluster.sh [options]`

**Options:** `--cluster-id`, `--existing-cluster-id`, `--run-id`, `--functions`, `--set core|full`, `--grid-bng-only`, `--benchmark-grid-bng`, `--spark-warmup`, `--spark-measured`, `--modes`, `--row-counts`, `--warmup`, `--measured`, `--heavyweight-only`, `--lightweight-only`, `--input-tile materialized|virtual`, `--grouped-file`, `--grouped-file-only`, `--multiwindow-corpus <path>`, `--levels <S|G|A|H|SE|IO>`, `--levels-only`, `--levels-scales <csv>`, `--levels-uc <catalog.schema>`, `--file-matrix`, `--file-matrix-only`, `--gpkg-chunksize`, `--gpkg-chunksize-only`, `--layout-sweep`, `--layout-sweep-only`, `--layout-scan`, `--layout-scan-only`, `--file-filespace <id>`, `--gpkg-corpus <path>`, `--max-partition-bytes <v>`, `--no-wait`, `--help`.

`--existing-cluster-id <id>` attaches the run to a warm all-purpose cluster, skipping the 4-8 min job-cluster startup. Passed through to the Python launcher; equivalent to setting `CLUSTER_ID` in the env file. (`--cluster-id` in the shell command sets the same env var for back-compat.)

`--set` chooses the tier (`core` default, or `full`). An explicit `--functions` overrides `--set`.

`--grid-bng-only` runs only the British National Grid benchmark (both tiers, then the exact-output parity gates); `--benchmark-grid-bng` adds it to a function run. `--functions` with `bng_*` names (e.g. `bng_kringexplode,bng_tessellateexplode`) runs just those BNG legs; names that are not `bng_*` do not filter it, and a `bng_*` name that is neither a BNG leg nor a registered bench function (e.g. a typo) stops the run. Each `*explode` leg times its own tier — the lightweight table function through `FROM t, LATERAL f(...)`, the heavyweight generator in the select list — and, when both tiers are registered, checks the two forms give the same row count.

Every two-tier leg of the grid (BNG, quadbin, custom), TIN, legacy, MVT/PMTiles aggregate and fan-out benchmarks reads the plan of the query it is about to time: a leg whose query runs the other tier's implementation stops the run with `TierResolutionError` instead of recording a row.

`--input-tile` selects the input tile mode for the light spark-path leg: `materialized` (bytes column, default — matches all prior bench runs) or `virtual` (path+window tile, exercises the virtual-tile reader path).

`--grouped-file` adds the grouped FILE-amortization benchmark: `rst_clip_grouped` plus pixel-op `_grouped` fns run df→df over a MULTIWINDOW COG corpus (many windows per source), timed across three tile modes — materialized, virtual+FILE-off, virtual+FILE-on. This is the leg that exercises `grouped_tile_map`'s per-source open-cost amortization (the FILE win the scalar bench misses); the leg toggles FILE on/off internally per mode, so do not combine it with `--disable-file`. `--grouped-file-only` runs just that leg. `--multiwindow-corpus <path>` points at the corpus dir holding `cog_multiwindow_manifest.json` (default `<corpus>/bench-corpus-cog-multiwindow`); the leg skips cleanly if the manifest is absent.

`--levels <S|G|A|H|SE|IO>` adds the levels leg for one set of functions (`S` session functions, `G` generators, `A` aggregates, `H` DataFrame helpers, `SE` the GDAL spec engine's rows (slope, transformcrs, mapalgebra against today's implementations); `IO` has no forms yet): every form of that set timed at each execution level the compute offers — L1 (Catalyst expression), L2 (Java UDF), L3 (light), L4 (Unity Catalog function) — at 1x/4x/16x its base row count, one row per form and scale in the same results table. Each row carries `level`, `form` and `compute` (`dedicated`, `standard` or `serverless`, detected from the session) and the attribution split: bytes sent to / returned from Python workers, Python-worker task-seconds (`py_eval_s`) and their share of the execution's executor task-seconds (`py_eval_frac`, in (0, 1]), shuffle and spill bytes, peak execution memory, GC seconds and the Python workers' peak RSS. The split is the plan of the last measured iteration (the timing is the median over all of them). A classic session reads it from the driver's Spark REST API; a Connect session (standard access mode, Serverless) reads it from the query's `executionInfo`, which has no GC time. A metric with no value is NULL, never 0, and the row's `note` says why: `unavailable: ...` for what the session could not report (the REST API leaves out a metric no node ever updated, so "no spill" reads as NULL on a classic session), nothing for what does not apply (a JVM level or a Unity Catalog function has no Spark Python worker). `py_worker_rss_mb` is the kernel's high-water mark of the Python workers that ran the shape, reset on every worker just before it ran, so it is that shape's peak and not an earlier one's; an idle pooled worker is not counted. It needs Linux, a classic session whose default parallelism matches the executors' slots (read from the Spark REST API), and a fixed-size cluster that nothing else is using (the reset waits up to 60 s for a free slot on every worker). Otherwise it is NULL with the reason in `note`, and always on Connect. It is also NULL rather than a number that may leave a worker out: when no Python worker ran during the shape; with `spark.python.worker.reuse=false`; when a worker that was there at the reset has exited, in any pool, another pool's idle worker included (the reading cannot tell that it did not run; Spark stops a worker that has idled 60 s, so a long shape in a pool with idle workers, or whose early tasks end long before its last, is NULL); when the REST API shows a failed, killed or retried task, or gives no answer for the shape's jobs; when a shape longer than 50 s has a wait of more than 50 s between task ends on an executor (a worker created by the shape may have idled out and been stopped); when the shape's physical plan has an early stop (`CollectLimit`, `GlobalLimit`, `LocalLimit` or `TakeOrderedAndProject`: a `take`, `head`, `first` or `limit` can end a worker before the read without failing a task) or the plan cannot be read; when the shape ran Python workers in more than one environment (two pools that ran on one executor: a cold pool has no baseline, so a worker of one can exit unseen while the other keeps releasing); and when the executors' slots differ from the default parallelism, a live worker cannot be reset, or no slot frees up within 60 s. The row's `note` gives the reason in each case. Known limits, documented and not coded (none is NULL, and none is checked): a consumer other than a limit node that stops reading early without failing a task (for example a sort-merge join that exhausts one side over sorted input) can end a worker unseen; a JVM tail of more than 10 s after a task's Python output ends defeats the margin of the 50 s guard (the 60 s is OSS Spark 4.0.0's idle constant, not checked on DBR); and the early-stop check reads only the DataFrame the shape ran, so an early stop in another query, or a `run` callable that reads rows on the side, is not seen (no bench form does one). `ser_sent_bytes` is NULL unless it grows with the row count across the scales, because Spark stops counting the numeric input it sends past one Arrow batch. `native_s` is NULL until a level reports it. For the BNG function the leg also times a `floor` form: the same Arrow UDF shell and input with a constant body, so its median (`floor_median_s` in the summary table, beside each variant's median at the same row count) is what the shell costs without a kernel; `py_eval_frac` cannot tell the two apart, because a stage whose time is the UDF scores about 1 either way. A form whose function returns NULL for some rows is an `error` row ("N of M outputs NULL") unless the form allows it. Tile inputs are cached next to the results table from `<corpus>/rows` (the leg skips the raster forms with a `na_by_design` row when it has none); L1 and L2 need the geobrix JAR on the cluster. `--levels-uc <catalog.schema>` is where the L4 functions were created (`gbx:uc:sql` / `databricks.labs.gbx.uc`); without it the L4 forms record a skipped row. `--levels-only` runs just this leg, without the heavy tests JAR.

**Phase-2 FILE legs (light-only, serialized, each `*-only`-capable):**

`--file-matrix` adds the FILE-access matrix: GeoTIFF + GeoPackage reads swept across `file_mode` ∈ `{fuse, external, managed}`. Each mode runs fully isolated (no cross-mode warm state). GeoTIFF reuses `{corpus}/rows` (10k tiles, exceeds cluster slots). GeoPackage stages a copies-ladder corpus at `--gpkg-corpus` automatically (idempotent). `external`/`managed` yield `na_by_design` on FUSE-only tiers. `--file-matrix-only` runs just that leg.

`--gpkg-chunksize` adds the GeoPackage chunkSize sweep (fuse mode, chunk sizes 1k/10k/100k) that confirms fanout-invariance (partition count must be stable across chunk sizes). Stages the same `--gpkg-corpus` corpus automatically. `--gpkg-chunksize-only` runs just that leg.

`--layout-sweep` adds the FILE write layout sweep: GeoTIFF tile_df (read from `{corpus}/rows`) and a single GeoPackage file are written across layouts `(order, cluster, plain)` each to an **isolated per-layout target** (no layout inherits a prior write's on-disk grouping). `cluster` layout runs `OPTIMIZE` after the write. Requires `--file-filespace` for FILE-table targets; falls back to fuse paths if not set. `--layout-sweep-only` runs just that leg.

`--layout-scan` adds the layout-scan comparison: sequential-scan + shuffle-input cost measured for each layout's FILE table (the tables must already exist from a `--layout-sweep` run). Skips cleanly if `--file-filespace` is not set. `--layout-scan-only` runs just that leg.

`--file-filespace <id>` passes the filespace identifier for FILE EXTERNAL/MANAGED table creation (e.g. a TBLPROPERTIES filespace path under a Volume). Default: empty string — managed/external legs yield `na_by_design`.

`--gpkg-corpus <path>` points at the GeoPackage bench corpus base dir (staged by `stage_gpkg_bench_corpus`). Default: `<corpus>/bench-corpus-gpkg`.

`--max-partition-bytes <v>` sets `spark.sql.files.maxPartitionBytes` (e.g. `32m`, `16m`) in the run's preamble to cap bytes-per-partition on file/Delta scans — smaller partitions mean fewer rows per task (less memory per decode task). Unlike AQE, this conf **is settable on Serverless**, so it works on both classic and `--serverless` runs. Default: empty (leave the platform default, 128 MB).

**Hardening (every run):**
- **Smoke first.** A SMOKE run goes before the real scales: a worker-side import check (a one-row UDF imports `databricks.labs.gbx` and reports its version and arch) and each form of the `--levels` set once at `--smoke-rows` rows (default 16), reporting the Spark task count of each form's input scan (a tile form over a one-file table runs on 1-2 tasks). Only a clean smoke submits the real run; otherwise exit 4. `--no-smoke` skips it (logged), `--smoke-only` stops after it, `--smoke-allow-errors` lets a form's error row through, `--smoke-timeout-min` (default 15) bounds it.
- **Preflight, no compute.** Exit 5 when the Serverless environment spec lacks the wheel (or the wheel's `+env<N>` is not the environment version), the staged wheel's sha256 is not the local `dist/env<N>` build, a levels form's SQL cannot run on a local Spark session with a few rows (a Java UDF inside `sum()`, a raw-hash sum that overflows under ANSI), or a client-built input would pass 64 MiB. `--skip-preflight` skips it (logged).
- **Time limits.** Every run has `timeout_seconds` (`--timeout-min`, default 120 with `--levels`, else 360).
- **Watchdog.** The notebook writes `<out_dir>/heartbeat.json` every 30 s (form in progress, its elapsed time, the working thread's stack) and sinks each form's rows when it finishes. The launcher cancels the run when the heartbeat stops changing for `--stale-min` (default 5) or one form passes `--form-cap-min` (default 15, smoke 5), prints `STALLED: <form> after <m> min` with the driver stack, and exits 3. It never retries. The notebook also arms `faulthandler.dump_traceback_later` at the cap (stderr of the driver).
- **Snapshot.** The command copies the scripts, the launcher and the bench package to a temp dir at launch and runs from it, so an edit during the run cannot change it (`GBX_NO_SNAPSHOT=1` runs in place).
- `--inject-stall <seconds>` (test only) adds a form that sleeps on the driver, to prove the watchdog.

**Interpreter:** the launcher needs `databricks-sdk` and Python 3.11 or newer. It does not use whatever `python` is on the PATH: the shared `gbx_python_with_sdk` helper in `common.sh` picks `.venv-pyrx` (or the venv in `GBX_PYRX_VENV`) when that venv is Python 3.11+ and can import the SDK (the CI-lock venv from `gbx:venv:sync` cannot), otherwise `uv run --with databricks-sdk==<pinned version>` layered over the venv's interpreter, so the venv's own packages (rasterio, the bench harness) stay importable; with no usable venv it uses Python 3.12 plus the SDK only; otherwise system `python3` if it is 3.11+ and has the SDK, otherwise it stops with a hint to install uv. The SDK is pinned (`GBX_DATABRICKS_SDK_SPEC` in `common.sh`) so a run does not float to a newer release.

**Examples:**
- `bash scripts/commands/gbx-bench-cluster.sh --cluster-id 0101-x --run-id cl1 --functions rst_slope,rst_ndvi`
- `bash scripts/commands/gbx-bench-cluster.sh --cluster-id 0101-x --run-id clfull --set full`
- `bash scripts/commands/gbx-bench-cluster.sh --cluster-id 0202-arm --lightweight-only` (ARM)
- `bash scripts/commands/gbx-bench-cluster.sh --cluster-id 0101-x --run-id virt1 --input-tile virtual`
- `bash scripts/commands/gbx-bench-cluster.sh --existing-cluster-id 0101-x --run-id bngx1 --grid-bng-only --functions bng_kringexplode,bng_kloopexplode --spark-warmup 1 --spark-measured 5`
- `bash scripts/commands/gbx-bench-cluster.sh --cluster-id 0101-x --run-id gfile1 --grouped-file-only --multiwindow-corpus /Volumes/geospatial_docs/geobrix/sample-data/bench-corpus-cog-multiwindow`
- `bash scripts/commands/gbx-bench-cluster.sh --existing-cluster-id 0101-x --run-id lv1 --levels S --levels-only --levels-uc main.gbx_uc`
- `bash scripts/commands/gbx-bench-cluster.sh --existing-cluster-id 0101-x --run-id lvh --levels H --levels-only --levels-scales 1,4` (`--levels-scales`: the multiples of each form's base row count; default `1,4,16`)
- `bash scripts/commands/gbx-bench-cluster.sh --serverless --run-id lvs --levels S --levels-only --levels-uc main.gbx_uc` (smoke, then the real run)
